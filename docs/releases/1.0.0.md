# WaveSink 1.0.0

WaveSink 1.0 is a cleanup and hardening release. Routing has been rebuilt around a
single model, everything now reaches your speakers through a mix, levels top out
at 100%, and the mixer gains live level meters. Leftovers from the original Sink
that no longer did anything are gone.

## Highlights

- **Live level meters** on every mix header, every route cell and every hardware
  input, drawn right inside the slider.
- **Mix level sliders** on the mix headers: one fader controls everything a mix
  sends to its outputs.
- **Omarchy audio panel integration**: your WaveSink mixes show up as sliders in
  the Omarchy bar's audio panel, and changes made there are saved by WaveSink.
- **No software amplification**: every level runs 0–100%, like Windows and macOS.
- **Solo an input**: right-click an input's icon to mute everything else.
- **Per-input Audio FX** on hardware inputs, replacing the old processed-mic chain.

## New

### Level meters
- Meters on mix headers, route cells and hardware inputs (up to 96 at once).
- The meter fills the slider itself, with peak hold; the fader knob sits on top.
- Route-cell meters show what that cell actually sends (input level × send level).
- Colors come from your theme: solid green through normal levels, warming
  toward the top, red from about 95%.
- **Pro Audio Metering** (Settings → Meters): dBFS scale, dB gain labels and a
  peak readout on hover. The sliders themselves still read 0–100.
- Meter rate setting: 10, 20 or 30 fps (default 30).
- "When unfocused" setting: drop to 10 fps (default), keep full rate, or pause.
- Meters stop entirely, and cost nothing, while WaveSink is hidden in the tray.

### Mixer
- Mix headers have a level slider: the single volume control for everything the
  mix sends to its outputs.
- Left-click an input to edit it, the same as mixes.
- Right-click an input's icon to **solo** it: every other input is muted and the
  soloed icon gets a green outline. Right-click it again to restore everyone's
  previous mute state. Right-clicking another input moves the solo. The solo
  survives a restart, so it can still be undone.
- New **"System default"** mix output that follows your desktop's default
  output device.

### Audio FX
- Hardware inputs (microphones etc.) can have their own Audio FX chain, applied
  before the input reaches any mix. This replaces the old standalone processed
  mic (`sink_mic`).

### Omarchy
- `wavesink --set-mix-volume <mix> <percent>` sets and saves a mix level from the
  command line or another app, without popping the WaveSink window up. The
  Omarchy audio panel plugin (`wavesink.audio`) uses this.

## Changed

- **All levels are capped at 100%.** There is no software gain anywhere in the
  audio path (EQ boost is still available). Saved levels above 100% are brought
  down to 100% on first launch.
- WirePlumber no longer restores old volumes onto WaveSink's nodes, so levels
  always come back exactly as WaveSink saved them.
- **Channels reach your outputs only through mixes.** Previously a channel also
  played straight to an output device, so a mix bound to the same device played
  everything twice.
- If you have no mix outputs set up yet, your first mix gets "System default" so
  nothing goes silent.
- New channels and mixes start **unrouted**: tick the cells you want.
- Routing, levels, mutes and profiles are now stored in one place
  (`routing.json`). Your existing setup is migrated automatically on first
  launch; the old files are copied to a `routing-migration-backup-<time>` folder
  next to it and never written again. Older profiles are converted when loaded.
- WaveSink now talks to PipeWire only (the `pactl` fallback is gone), so it no
  longer requires `pulseaudio-utils`. PipeWire's PulseAudio server
  (`pipewire-pulse`) is still required. If WaveSink can't reach PipeWire at
  startup it retries for a few seconds, then shows a dialog explaining the
  problem.

## Fixed

- Stereo channels on pro-audio devices (AUX0/AUX1 ports) could come out
  left/right swapped.
- Audio routed to a mix and also to the mix's output device played twice.
- The routing grid could show a channel as routed to a mix that wasn't actually
  carrying it (and mixes set to "include everything except" stored the wrong
  channels).
- A newly created mix didn't pick up its saved level at startup.
- Hardware input routes and mutes weren't always applied at startup.
- The same app could appear several times in Apps (for example OBS launched
  from a menu vs. from a terminal), each with its own assignment. It's now one
  entry, and existing duplicates are merged on startup. A Flatpak install that
  shares a name with a native one is labelled "(Flatpak)".
- Channel icons in the Apps "assign to channel" menu showed up as text instead
  of icons.
- The Edit Mix dialog couldn't be scrolled all the way down.

## Removed

These had no UI left to reach them, or were replaced by something above:

- Default input/output device pickers (use your desktop's sound settings).
- The "Device naming" setting.
- The processed virtual mic as a mix member (replaced by per-input Audio FX).
- Balance / ChatMix and its hotkeys.
- Mix roles (every mix is a recording mix), hidden devices.
- The mix send-levels pop-out window (route cells set send levels directly).
- "Listen to a mix" monitoring.
- Per-channel output device and failover settings (mixes own outputs now).

Old config files with these settings still load; the settings are ignored.
